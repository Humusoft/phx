How PHX Thinks — Core Concepts

The handful of object types every scene is built from

Every scene is built from just a handful of object types. Once you understand them, the rest is only a matter of combining them.

ObjectWhat it represents
phx.Simulation The whole scene and its “engine”. Holds time and gravity, and steps the computation.
phx.Body A rigid body — it has a position, mass, velocity and a shape. The basic building block.
phx.shape.* The geometry a body “wears” — box, sphere, cylinder, imported mesh … See Bodies and shapes.
phx.*Joint A connection of two bodies with restricted motion (hinge, ball joint, gear). See Joints, springs and ropes.
Forces and fields Spring, Rope, Thruster, Resistance, Buoyancy, Monopole, Dipole — springs, actuators, environmental drag, floating, gravitational/magnetic interaction.
Assemblies phx.assembly.* — prefab builders that create whole groups of parts at once (an arena, a jointed chain, scattered bodies, an imported model). See Prefab assemblies.
Observers Logger (data logging), Trace (motion trail), Measure (distances and velocities), Zone (bodies inside a region), Raycast (ray sensor). See Measuring and logging.
Automation Script (prescribed value profiles over time), Function (custom computation/control at every step), Camera (view attached to bodies). See Automation and control.
Visualization PlanarShadow (shadow of bodies projected onto a plane) and the enhanced viewer phx.extra.Viewer. See Interactive viewer.

Three steps of every scene

  1. Build — create the bodies and their links (in any MATLAB axes).
  2. Run — create a phx.Simulation and call step.
  3. Evaluate — read body properties or data from a Logger.
% the skeleton of every scene
clf; view(3); axis equal; grid on; camlight headlight;   % scene
phx.Body(...);                                           % bodies
phx.Body(...);
sim = phx.Simulation;                                    % engine
sim.step(interval, substeps);                            % run
delete(sim);                                             % cleanup

Stepping — the step method

The most important simulation command:

sim.step(interval, substeps, redrawStep)
  • interval — how many seconds to simulate,
  • substeps — into how many sub-steps the interval is split (computation granularity),
  • redrawStep — optional: on which sub-steps a redraw is requested (default 1 = every one), 0 for no redraw during the step, -1 for no graphics at all.

How often the view is actually redrawn is decided by the RedrawMode property. The default "adaptive" redraws as often as the screen and the cost of drawing allow, at most once per display frame, and skips the rest; the scene stays alive during the run, it can be orbited, zoomed and picked while it is being simulated. Usually there is nothing to set:

sim = phx.Simulation;
sim.step(5, 1000);            % 5 s in 5 ms substeps, drawn as often as it pays off

Two properties tune the picture. PacingRate limits the speed of the run, 1 keeps it at most in real time. FrameSpacing sets how much simulation time may pass between two frames of a fast run (default 1/20 s); raise it for long time scales. When every frame matters, as in a recorded video, use "full"; for timing measurements with a fixed number of frames, use "performance"; both redraw exactly on the sub-steps asked for by redrawStep:

sim = phx.Simulation(ax, "RedrawMode", "performance");
sim.step(5, 1000, 10);        % a frame on every 10th substep
Note. A smaller step (more substeps) = a more stable but slower computation. Tightly coupled scenes — joint networks, stacks in contact — call for a finer step; see Units, scale and engine settings. Bodies can also be added to a running simulation with sim.addObjects(b).
