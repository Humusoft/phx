phx.assembly.import

Import a multi-body model from a file or a rigidBodyTree

Function  phx.assembly.import  |  Package: phx.assembly

Description

phx.assembly.import reads a model file and creates the phx.Body objects it describes. The format is chosen from the extension: a URDF (.urdf, .xml) file becomes one body per link connected by joints; a Wavefront OBJ (.obj) file becomes one body per object (o/g group) with no joints; an STL or PLY file becomes a single body. To load an OBJ as one merged body instead of separate parts, use phx.shape.Mesh.

Instead of a file, the function also takes a rigidBodyTree object of Robotics System Toolbox, creating one body per rigid body of the tree and one joint per tree joint. This reaches everything importrobot reads — Xacro and SDF files, robot description text and Simscape Multibody models — and the robot library of loadrobot. See rigidBodyTree to PHX mapping.

OBJ objects import as dynamic bodies with a convex collision envelope (set Envelope to override), each body frame at its object's centroid. Only genuine 3D solids are imported — flat objects (ground planes, light quads, decals) and line- or point-only objects carry no useful collision volume and are skipped. A URDF file also creates a joint for every revolute, continuous, prismatic or fixed joint of the robot. Despite the name of the format, URDF files describe more than robots — ragdolls, vehicles, furniture and single-body props from public model libraries import the same way. The assembled model is placed in its zero (home) configuration with the base at the world origin, unless a pose is given by the Position and Orientation or EulerAngles options.

Creation

Syntax

bodies = phx.assembly.import(file) bodies = phx.assembly.import(tree) [bodies,joints] = phx.assembly.import(___) [___] = phx.assembly.import(___,Name,Value) [___] = phx.assembly.import(ax,___)

Description

bodies = phx.assembly.import(file) creates the bodies in the current axes and returns them in a struct whose field names are the link names (made valid MATLAB identifiers; the original URDF name is preserved in the Name property).

bodies = phx.assembly.import(tree) imports the rigidBodyTree tree instead of a file, one body per rigid body that carries mass or geometry, its base included.

[bodies,joints] = phx.assembly.import(___) also returns all created joints in a struct keyed by the joint names.

[___] = phx.assembly.import(ax,___) draws into the given axes instead of the current axes; an empty target ([]) creates the bodies without graphics for headless simulations.

Options

The base-pose options apply to every format. The remaining options are specific to one branch — passing a mesh option to a URDF file, or MeshPath to a mesh file, raises phx:import:unsupportedOption.

OptionDefaultDescription
Position[0 0 0]World position of the base (root link frame).
Orientationeye(3)World rotation of the base as a 3×3 rotation matrix. Same convention as phx.Body.Orientation.
EulerAngles[0 0 0]World rotation of the base as Euler angles (z→y→x order), an alternative to Orientation.
MeshPath""URDF only. Root folder used to resolve package:// URIs and relative file names of mesh geometries. Meshes are always searched relative to the folder of the URDF file as well.
ConfigurationhomeConfiguration(tree)rigidBodyTree only. Joint configuration the tree is imported at, in the data format of the tree (see DataFormat); a plain vector of joint positions is accepted for the "struct" format as well.
Scale[1 1 1]Mesh files only. Scale factor applied to the imported mesh.
Envelope"convex"Mesh files only. Collision envelope of every imported body: "box", "cylinder", "sphere", "convex" or "concave". See phx.shape.Mesh.
FlipFacesfalseMesh files only. Reverse the triangle winding of the "concave" collision mesh when its solid side comes out wrong.
Density1000Mesh files only. Volumetric density of the imported bodies, kg/m³. URDF masses come from the inertial elements instead.

URDF to PHX mapping

Every link becomes a phx.Body with the body frame at the origin of the link's first visual geometry (PHX shapes are always centred at the body origin). Geometries map to Box, Cylinder, Sphere, Capsule (a common vendor extension) and STL and OBJ meshes with the convex collision envelope. Joints of type revolute and continuous become phx.RevoluteJoint, prismatic joints become phx.PrismaticJoint (sliding along the joint axis) and fixed joints become phx.FixedJoint. Planar joints have no direct equivalent yet and are approximated by a phx.GenericJoint with a warning; floating joints impose no constraint, so no joint is created and the child link is left free. Joint limits are ignored and all joints are passive — no motors are created. Masses come from the inertial elements; only the diagonal of the inertia tensor expressed in body axes is used.

rigidBodyTree to PHX mapping

A rigidBodyTree follows the URDF rules with these differences:

  • Geometry comes from the visuals of each rigid body, which the tree reports already tessellated, so every shape becomes a phx.shape.Mesh and no mesh files are searched for. A visual that the tree describes as a box, cylinder or sphere gets the matching bounding collision envelope, anything else the convex one. Collision geometry added to a rigid body separately (addCollision) is not used.
  • Joints are fixed, revolute or prismatic, the three types a tree knows. Both joint frames come from the fixed transforms of each rigidBodyJoint, so a tree built from Denavit-Hartenberg parameters assembles just as one imported from a file, and the Angle of a revolute joint (the Distance of a prismatic one) reads the joint position of the tree. A configuration solved by inverseKinematics can therefore be commanded to the joint motors as it stands; mind that Angle is wrapped to [−π, π].
  • Frames — rigid bodies with no mass and no geometry attached by a fixed joint, such as a tool or sensor origin — are merged into the nearest ancestor that is a part. Neither the frame nor its joint appears in the returned structs; the frame itself is still available from the tree through getTransform.
  • Masses come from the Mass and Inertia properties of each rigid body. The base of a tree carries no mass properties and borrows those of the lightest body of the tree, so that the solver does not face an extreme mass ratio. A robot standing on its own base wants a mass of its own, or a static base.
  • The tree is imported at the Configuration option, the home configuration by default. Joint limits (PositionLimits) are ignored.

Examples

Import a robot and anchor its base

clf; view(3); axis equal; grid on; camlight headlight;

[bodies, joints] = phx.assembly.import("robot.urdf");
bodies.base.Type = "static";

sim = phx.Simulation(bodies);
sim.step(1, 500, 5);
delete(sim);

Import a robot from the Robotics System Toolbox library

tree = loadrobot("kinovaGen3", "DataFormat", "row");
[bodies, joints] = phx.assembly.import(tree);
bodies.base_link.Type = "static";

Place a ragdoll leaning over an edge

[bodies, joints] = phx.assembly.import("human.urdf", ...
    "Position", [-0.16 0 2.6], "EulerAngles", [0 0.66 0]);
