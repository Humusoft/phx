Saving and Loading Scenes

Keeping a built scene in a MAT file and bringing it back

A scene is a set of phx.Body objects, so it is stored with the ordinary MATLAB save command and read back with load — there is no separate scene format. Saving the bodies is enough: everything attached to a body (its shapes, joints, springs, ropes, thrusters, loggers, zones …) is a child of that body and is written to the file with it.

A MAT scene is what the Simulink block reads, what the viewer’s Load model / Save model context-menu items write, and the usual way to keep a large model — an imported robot, a vehicle — out of the script that simulates it.

Saving a scene

Save the variables holding the bodies. Their names do not matter: on loading, PHX picks every phx.Body it finds in the file and ignores anything else stored alongside them.

ground = phx.Body("Type", "static", "Shape", {"Box", "Size", [6 6 0.3]});
arm    = phx.Body("Position", [0 0 2], "Shape", {"Box", "Size", [1 0.2 0.2]});
phx.RevoluteJoint(ground, arm, "PointA", [0 0 2]);

save("scene.mat", "ground", "arm");   % the joint is a child of both, it travels along

To store whatever is currently drawn in an axes — the form the viewer uses — collect the bodies first:

bodies = phx.Simulation.findBodies(ax);
save("scene.mat", "bodies");

For a larger model it pays to keep the parts named, so that the script loading it can address them individually. Build a struct and write it out field by field with -struct:

model.chassis = chassis;
model.wheels  = [wheelFL wheelFR wheelRL wheelRR];
save("saved_buggy.mat", "-struct", "model");
Note. Save the bodies, never the phx.Simulation object. The simulation owns a live engine world, which cannot be serialized; a file containing one reloads as a broken object.

Loading a scene

phx.Simulation accepts a file name and loads the scene itself. This is the shortest form, and it needs no figure:

sim = phx.Simulation("scene.mat");
sim.step(2, 400, -1);          % headless run, no redraw
delete(sim);

The bodies come back unparented — their graphics exist but belong to no axes. Hand them one with propagate, which sets a property on an object and all of its children:

clf; ax = gca; view(3); axis equal; grid on; camlight headlight;

sim = phx.Simulation("scene.mat");
sim.propagate("ParentAxes", ax);   % show the whole scene in these axes
sim.step(2, 400, 1);

When the parts have to be reached by name, load the file yourself and keep the struct. The bodies are parented as a group, and the simulation is created from the same struct (or from the axes, once the scene is drawn there):

model = load("saved_buggy.mat");
propagate(cell2mat(struct2cell(model)), "ParentAxes", ax);

model.chassis.Color = [1 0 0];                                % parts stay addressable
groupTransform(cell2mat(struct2cell(model)), "Translation", [-3 0 0]);

sim = phx.Simulation(model);

Bodies within a loaded scene are found by name as usual, with sim.findBy("Name", "chassis"). A file can also be dropped into a simulation that is already running — addObjects takes a file name too and rebuilds the execution pipelines:

added = sim.addObjects("scene.mat");

What the file holds

Saved with the bodies:

  • The object tree — shapes, joints, springs, ropes, force elements, loggers and every other child of a saved body, with its properties.
  • The graphics of each object (the hgtransform and its primitives, colors and textures included), so a reloaded scene looks the way it was built.
  • The full kinematic state — pose and both velocities. They are read from the engine as the file is written, and deleting a simulation copies them back into the objects as well, so a scene saved during or after a run reloads exactly where it stopped. The velocities are handed to the engine again when the scene is next simulated, and the motion continues instead of restarting from rest.

Rebuilt when the scene is simulated again:

  • The engine counterpart of every object — engine handles are transient and are recreated by the first phx.Simulation the scene is added to.
  • The execution pipelines, which the simulation builds for the loaded objects.
  • The link to an axes: a loaded scene is unparented until ParentAxes is set.
Tip. The shipped examples follow this split: a model_*.m script builds the bodies and saves them, and the phxex_*.m demo loads the MAT file, parents it into the viewer and simulates it. Keeping the model in a file takes a long build out of every run and lets several demos share one machine.
